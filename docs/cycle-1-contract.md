Этот файл — контракт **цикла 1**. Контракт горячего лида (выход продажи → вход CRM) ему не принадлежит: это стык циклов 2→3.

Движок: `LeadGenerationEngine`. Он смотрит присутствие бизнеса, понимает оффер из **его же слов**, ищет людей и оставляет только тех, у кого есть причина. Письмо человеку — не здесь. Живой справочник людей в этом репозитории **не подключён**. Это не продакшен-генерация.

## Вход: присутствие бизнеса

Владелец не печатает объявление в папку. Достаточно указателя на **её** публичный сайт. Движок сам читает эту страницу.

Допустимый вход:

- URL её сайта или лендинга (основной вход);
- по желанию — файлы в [`owner-materials/`](../owner-materials/), если она сама хочет добавить копию.

Не вход:

- чужие объявления, снятые скрейпом;
- платный/закрытый контент;
- секреты, ключи, `.env`;
- подключение Bing / Google / Meta Ads по OAuth (владелец введёт секреты сама, отдельным шагом);
- скрейп Google Ads Transparency Center;
- Microsoft Ad Library как ядро (там только показы EEA, рынок продукта — США).

## Понимание оффера и аудитории

Движок берёт слова **со страницы бизнеса**. Утверждение проходит, только если оно уже есть в этих словах. Цену, скидку, гарантию и юридическое утверждение он не выдумывает.

| Поле | Смысл |
| --- | --- |
| **what_we_sell** | Что продаём — цитата со страницы |
| **who_may_fit** | Кому это может подойти — тоже цитата |
| **commercial_claims** | Цена и прочее — только если уже написаны на странице |
| **must_not_promise** | Чего на странице нет: обещать нельзя |

Нет понятного «что» и «кому» — оффера нет, поиск людей не начинается. Отраслевых вилок в коде нет. Business DNA из продажи не копировать.

Код: `src/evorove_lead/engine.py`, оффер: `src/evorove_lead/offer.py` / `offer_reader.py`, страница: `src/evorove_lead/presence.py`.

## Выход: кандидат

Результат цикла — не «база контактов». Запись допустима только если есть все три поля:

| Поле | Смысл |
| --- | --- |
| **identity** | Личность, которую цикл 2 **потом** сможет адресовать (не отправка сейчас) |
| **reason** | Почему этот человек здесь, привязка к офферу/аудитории |
| **reason_source** | Откуда взялась причина |

Запись **без причины отклоняется**. Контакта мало. Движок не дописывает оффер к телефону, чтобы «подошло».

Это ещё не продажа, не карточка CRM и не слот.

### Handoff 1→2

Найденный человек + причина + источник + канал, которым цикл 2 потом можно писать. Объект handoff **не отправляет** сообщение. Пока между репозиториями нет очереди/API — контуры не склеены.

Горячий лид — **не** этот контракт.

## Явные не-цели

Цикл 1 **не** делает:

- исходящее письмо, SMS, звонок, очередь «написать на этот телефон»;
- разговор продажи, возражения, GREET, цитаты цены сверх страницы;
- календарь, бронь, смету, `ProcessEngine`;
- виджет или intake «нам уже написали»;
- скрейп LinkedIn;
- `SalesStage` / `ProcessState`;
- Lemon Squeezy, Twilio, встраиваемый чат.

## Рекламные библиотеки и кабинеты

| Источник | Статус |
| --- | --- |
| Публичный сайт бизнеса, который указал владелец | Вход движка |
| Microsoft Ad Library API | Позже, опционально, только EEA — не ядро США |
| Google Ads Transparency Center | Не скрейпить |
| Bing / Google / Meta Ads (свой кабинет) | Отдельный шаг с OAuth; секреты вводит владелец |

Поиск людей — порт `PeopleSearch`. По умолчанию `UnconnectedPeopleSearch`: оффер понят, людей ещё нет. Подключать живой источник без OAuth-секретов владельца и без скрейпа LinkedIn.
