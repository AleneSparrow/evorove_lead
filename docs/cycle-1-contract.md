## Как собираем данные

Три захода. Следующий не начинается, если предыдущий пустой.

### 1. Бриф — не лиды

**Откуда:** публичный сайт клиента (указала URL), по желанию её файлы, по желанию её открытые объявления (Microsoft Ad Library — только бриф, показы EEA, не люди США).

**Что достаём:** услуга; кому может подойти; география (США, город/зона, если есть); чего нельзя обещать (цены/скидки/гарантии/юрclaim, которых нет у неё на странице).

Сайт клиента **запрещён** как источник людей: ни формы, ни «нам написали», ни комментарии «я ваш клиент».

Бриф не готов — в интернет за людьми не идём.

### 2. Следы в свободном поле — ещё не лиды

**Откуда:** открытый веб по запросам из брифа (услуга + аудитория + место). Публичные страницы, посты, объявления о потребности, локальные следы. Не LinkedIn-скрейп, не пейвол, не внутренности Google Ads Transparency, не купленная база телефонов.

**Что кладём в склад анализа (след):** URL, дата съёма, текст/видимое, какой запрос из брифа привёл, язык, намёк на гео.

След про клиента (его же сайт, его же отзыв «я хожу сюда») — не след для генерации.

### 3. Люди из следов — ещё не Cold

Из следа, который прошёл анализ, извлекаем: имя если есть, email и/или телефон, факт о **его** ситуации, URL источника, канал `email` или `sms`.

Нет факта или нет контакта — в складе как отказ, не в CRM.

## Как анализируем и по каким метрикам

Не «есть ли слова H1 сайта в строке». Качество — ответ на вопрос: **этому человеку услуга этого клиента в США реально может подойти, и цикл 2 сможет ему написать.**

### Анализ брифа

| Метрика | Проход |
| --- | --- |
| Есть услуга | Понятно, что продаём, из её слов, без выдумки |
| Есть аудитория | Понятно, кому это живое дело |
| Есть рынок | США; локальность, если дело локальное |
| Коммерция | Не обещаем то, чего нет у неё на странице |

Любая дыра → статус «бриф не готов», поиск людей стоп.

### Анализ следа (сырые данные)

| Метрика | Проход |
| --- | --- |
| Не свой сайт | Документ не принадлежит клиенту |
| Тема | След про потребность / аудиторию / ситуацию, не про что попало |
| Гео | США или зона услуги, если зона в брифе |
| Открытость | Публичный http(s), не логин, не пейвол |
| Свежесть | След ещё имеет смысл (не архив десятилетней давности без живого сигнала) |

След не прошёл → храним отказ в складе анализа, людей из него не собираем.

### Повторный анализ человека (качество лида)

Все пункты обязательны. Нет одного — не Cold.

| Критерий | Качественный лид | Брак |
| --- | --- | --- |
| **Адрес** | Валидные email или телефон, канал ясен | Голое имя, ник, «есть в интернете» |
| **Факт** | Конкретная ситуация человека (ищет услугу, описывает задачу, публично просит помощи в этой теме) | «Есть телефон», повтор слогана клиента, пустая строка |
| **Источник** | Откуда факт: URL или явная фиксация съёма | «базы», «LinkedIn dump» |
| **Совпадение с услугой** | Факт бьётся с тем, что клиент продаёт | Соседняя ниша, конкурент, который сам продаёт то же |
| **Совпадение с аудиторией** | Человек из круга «кому это может подойти» | Случайный контакт в том же городе |
| **Гео** | США и зона, если зона есть | Другая страна при локальном деле |
| **Не свой** | Не действующий клиент этого бизнеса по следу | «Хожу к вам каждую неделю» |
| **Не свалка** | Одна живая причина, не список номеров | Купленный файл, дописанный оффер к телефону |

Оценка в складе анализа (для отладки, не для владельца как дашборд):

- **fit** — насколько факт и бриф про одно дело (0–1);
- **evidence** — насколько факт конкретный и привязан к источнику (0–1);
- **addressable** — 1, если контакт пригоден для цикла 2.

На Cold идут только те, у кого все три выше порога **и** все критерии таблицы «да». Порог не «процент закрытия клиенту». Это внутренний отбор, чтобы на доске не было мусора.

Владельцу на Cold видна **причина человеческим языком**, не баллы. Баллы остаются в складе анализа.

## Кому писать на холодную

Пишет **цикл 2**, не цикл 1. Цикл 1 решает только: **можно ли положить на Cold**.

Класть в CRM Cold, если:

1. Бриф готов.
2. Человек извлечён из открытого следа, не с сайта клиента.
3. Повторный анализ пройден (таблица выше).
4. Есть причина + источник + канал.
5. Его ещё нет на доске этого тенанта с тем же контактом.

Не класть, если нет согласия на отправку: согласие проверяет цикл 2 в момент письма (TCPA / opt-in / STOP). Качественный лид ≠ «уже можно слать SMS». Качественный лид = «есть зачем писать и чем адресовать». Без разрешённого согласия цикл 2 не отправляет, карточка может остаться в Cold.

## Код сейчас (честно)

Сайт клиента читается как текст. Отбор в коде всё ещё цепляется к цитатам страницы — это **старая неверная метрика**, её менять под этот контракт. Поиск по умолчанию не подключён. Cold в CRM из генерации не наполняется.

Склад анализа (Postgres цикла 1) физически есть: таблицы `briefs`, `hypotheses`, `traces`, `rejected_traces`, `candidates`, `hypothesis_outcomes`, тенант-скоуп по `business_id` (миграции в `migrations/`, порт 5435, отдельная база от `evorove`/`evorove-crm`). `LeadGenerationEngine` пишет туда сырой след и решение по каждому кандидату при наличии `business_id` — без похода в CRM. Пока нет `hypothesis.py` (фаза 1), каждый прогон открывает одну временную гипотезу "unstructured" на снимок брифа — это мост, не `HypothesisSet`; реальные сегменты аудитории и триггеры намерения появятся в фазе 1.
