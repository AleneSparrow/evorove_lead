# SearxNG

Клиент — `HttpSearxngWebSearchClient`. База задаётся `WEB_SEARCH_BASE_URL` и может быть localhost: это свой инстанс, не URL из выдачи. URL из выдачи и редиректы проходят `validate_public_http_url`.

Поведение клиента:

- JSON `results[].url` и `content` сохраняются как пришли; дедуп сравнивает нормализованный URL, в складе остаётся исходный.
- `pageno` используется, когда `max_pages` больше 1. Конструктор по умолчанию читает одну страницу.
- Таймаут, обрыв и не-JSON дают пустую выдачу, а не исключение наружу.
- Повтор того же запроса в одном клиенте берётся из памяти.
- `LEAD_MAX_SEARCH_REQUESTS` (через `client_from_env`, по умолчанию 30; `0` снимает потолок) останавливает новые HTTP-вызовы.

Локальный инстанс описан в `docker-compose.yml` и `searxng/`. В этой среде Docker не поднимался, поэтому живой SearxNG-контейнер здесь не проверен. Юнит-тесты гоняют формат ответа на подставном HTTP.

Спам в сниппете не скачивается. Отсутствие точных слов услуги больше не отменяет fetch: страница остаётся кандидатом для prefilter и, если включён провайдер, для Sonnet.
