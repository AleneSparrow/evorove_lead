# Поиск лидов

Живой поиск — это свой SearxNG (`WEB_SEARCH_BASE_URL`) и свой разбор публичной страницы. Платный поисковый API не вшит. Без базового URL движок остаётся `search_unconnected` и не печатает выдуманных людей.

## Что делает коннектор

`WebSearchPeopleSearch.find` на одну гипотезу:

1. Один запрос `query_template`, собранный из брифа (`hypothesis.py`): аудитория, `business_listing`, `"looking for …"`, `"need …"`, плюс город, если он задан.
2. Кэш успешного ответа в процессе. Пустой транспортный сбой не кэшируется.
3. До 3 попыток на обрыв сети (`LEAD_SEARCH_ATTEMPTS`, потолок 5). Пауза между попытками короткая. `LEAD_SEARCH_MIN_INTERVAL_SECONDS` ограничивает частоту, по умолчанию 0.
4. До скачивания страницы: нелатинский текст, явная чужая страна при зоне США, дата старше 548 дней, если дата вообще пришла в `publishedDate`. Дату код не выдумывает. Нет даты — след не считается старым.
5. Повторный URL в том же ответе не качается второй раз. Текст страницы кэшируется на время объекта коннектора.
6. Публичный http(s), не площадка-каталог для B2B, почта или строгий телефон. Телефон без пунктуации не берётся.

Гипотеза с тем же `query_template`, у которой последняя строка склада `paused` или `query_budget = 0`, в этом прогоне не ищется.

## Классы следа

| Класс | Смысл | Cold на живом пути |
| --- | --- | --- |
| `EXPLICIT_INTENT` | Просьба или поломка и слово услуги | Да, если есть контакт и источник |
| `INFERRED_OPPORTUNITY` | Просьба и слово аудитории, без слова услуги | Да, на тех же условиях |
| `ICP_MATCH` | Совпадение с аудиторией. Для компании это и есть лид B2B | Компания — да. Человек — нет |
| `INSUFFICIENT_EVIDENCE` | Слово услуги без просьбы, или нет источника | Нет |
| `IRRELEVANT` | Не про оффер или это конкурент | Нет |

Голое совпадение слов не получает класс `EXPLICIT_INTENT`.

## Чего коннектор не делает

Не ходит в LinkedIn, не читает пейвол, не покупает базу, не шлёт письмо. Охват равен тому, что отдаёт конкретный SearxNG владельца.
